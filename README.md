# Forever Meta

[![Сборка и деплой](https://github.com/medivhkr/forever-meta/actions/workflows/deploy.yml/badge.svg)](https://github.com/medivhkr/forever-meta/actions/workflows/deploy.yml)

Тир-лист спеков World of Warcraft по реальным логам [Warcraft Logs](https://fresh.warcraftlogs.com). Сейчас сайт считает TBC Anniversary, а когда в WoW Forever откроются рейды (9 декабря 2026), переключится и на него.

**Сайт:** https://medivhkr.github.io/forever-meta/

## Что умеет

- Тир-лист S–D по каждому рейду. Цвета тиров — цвета качества предметов в игре.
- Переключатели роли (урон, лечение, танки) и метрики (медиана 100 лучших парсов, среднее 10 лучших, рекорд).
- Тепловая карта «спек × босс»: видно, на каком боссе спек проседает.
- Страница босса: рейтинг спеков и лучшие игроки со ссылками на логи.
- Страница спека: место и доля от лучшего на каждом боссе.
- **База предметов**: 589 эпических предметов из восьми рейдов TBC с фильтрами по рейду, слоту, броне и роли. Названия, иконки и характеристики на русском — из базы Wowhead, списки добычи по боссам — из AtlasLoot.
- **Подсказки предметов в стиле игры** при наведении: уровень, броня, характеристики, гнёзда, эффекты, комплекты.
- **Персонажи**: 56 демо-героев (по два на спек) в настоящей рейдовой экипировке. При наведении на имя видно, что надето; на странице персонажа — «кукла» как в оружейной, сумма характеристик и результаты по боссам.
- Добыча на странице каждого босса и поиск по персонажам и предметам в шапке (Ctrl+K).
- **Конструктор экипировки**: собери комплект из 589 предметов, сравни с любым персонажем, поделись сборкой ссылкой.
- **Радар по боссам** на странице спека со сравнением двух спеков.
- **Приложение на телефоне**: сайт ставится как PWA и открывается без интернета.
- **Оформление в духе Apple**: светлая и тёмная тема, тир-лист как домашний экран iPhone, поиск как на apple.com.
- Роль и метрика хранятся в адресе, поэтому любой вид можно отправить ссылкой.

## Дизайн

Ориентир — сайты и интерфейсы Apple: белые и светло-серые поверхности, шрифт SF Pro на устройствах Apple и Inter на остальных, синие ссылки, тонкие линии вместо рамок. Тени только у того, что парит над страницей: шапка, подсказки, окна. Цвет несёт смысл: качество предметов и тиры (S — легендарный, A — эпический…), рост и падение характеристик, две серии на радаре. Цвета графиков проверены скриптом на различимость при дальтонизме и на контраст с фоном.

- Тир-лист — домашний экран iPhone: иконки спеков скруглены, как иконки приложений.
- Переключатели, тумблеры и окно выбора предмета повторяют элементы iOS; на телефоне окно выезжает шторкой снизу.
- Страница предмета устроена как «Технические характеристики» на apple.com.
- Тема: светлая, тёмная или как в системе. Выбор применяется до первой отрисовки, поэтому тёмная тема не мигает белым.

## Фронтенд-фишки

- **Дизайн-система на CSS-переменных** — токены цвета и типографики, тёмная тема переопределяет только их.
- **View Transitions API** — иконки «перелетают» между страницами, смена темы плавно перетекает (data router React Router 7 + `view-transition-name`).
- **Code splitting** — каждая страница отдельным чанком; код качается при наведении на ссылку, данные рейда — при наведении на вкладку (`queryOptions` + `prefetchQuery`).
- **PWA** — `vite-plugin-pwa` и Workbox: предварительный кеш кода, данные по сети с запасным кешем, иконки из кеша; своя кнопка «Установить».
- **Нативный `<dialog>`** в конструкторе: фокус, Esc и блокировка фона из коробки.
- **`useReducer` + чистые функции** для сборки, состояние синхронизировано с URL и `localStorage`.
- **`useEffectEvent`** — горячие клавиши поиска, **`useSyncExternalStore`** — статус сети, **`useDeferredValue`** — отзывчивый поиск.
- **Плашка переключателя как в iOS** — `useLayoutEffect` меряет выбранную кнопку до отрисовки кадра, CSS анимирует переезд.
- **Граница ошибок на уровне маршрутов** (`errorElement`) и восстановление прокрутки (`ScrollRestoration`).
- **Графики без библиотек** — радар на SVG, тепловая карта и полосы на CSS.
- **Тесты** — Vitest + Testing Library, запускаются в CI перед каждым деплоем.

## Как это работает

```
GitHub Actions, каждые 6 часов
  └─ scripts/collect.ts ── Warcraft Logs API v2 (OAuth client credentials + GraphQL)
       └─ public/data/meta.json, public/data/zone-<id>.json
            └─ vite build ── GitHub Pages
                 └─ React грузит JSON через TanStack Query и считает тиры в браузере
```

Сайт статический: своего бэкенда нет. Ключ API хранится в секретах репозитория и нужен только сборщику во время сборки, в браузер он не попадает. Если секретов нет, сайт собирается на демо-данных и честно об этом пишет.

API Blizzard для тир-листа не подходит: он не отдаёт урон и исцеление в бою. Эти цифры есть только в логах.

## Методика

1. На каждом боссе для каждого спека берём метрику по 100 лучшим парсам (по умолчанию медиану).
2. Делим на значение лучшего спека этой роли на том же боссе.
3. Усредняем доли по боссам рейда. Это оценка спека.
4. S — от 97%, A — от 92%, B — от 85%, C — от 75%, D — ниже.

Спеки с меньше чем 10 парсами на боссе на этом боссе не учитываются. Спек, который есть меньше чем на половине боссов, помечается «мало данных».

## Стек

React 19, TypeScript, Vite, React Router 7, TanStack Query 5. Без UI-библиотек: тиры, полосы и тепловая карта сделаны на CSS.

## Запуск локально

```bash
npm install
npm run demo-data   # демо-набор без ключа API
npm run dev
```

С реальными данными (нужен клиент на https://www.warcraftlogs.com/api/clients/):

```bash
WCL_CLIENT_ID=... WCL_CLIENT_SECRET=... npm run collect
```

База предметов и демо-персонажи пересобираются отдельно (нужен интернет, ключи не нужны):

```bash
node scripts/build-items.ts        # AtlasLoot + Wowhead → public/data/items.json
node scripts/demo-characters.ts    # демо-персонажи → public/data/characters.json
npm run demo-data                  # демо-рейтинги, игроки в них — эти персонажи
```

Настройки сборщика через переменные окружения: `WCL_SITE` (по умолчанию `https://fresh.warcraftlogs.com`), `WCL_ZONE_IDS` (явный список рейдов через запятую), `WCL_MAX_ZONES`, `GAME_VERSION`.

## Деплой

Push в `main`, запуск вручную или расписание запускают `.github/workflows/deploy.yml`: сбор данных → сборка → GitHub Pages. Для реальных данных в секретах репозитория должны быть `WCL_CLIENT_ID` и `WCL_CLIENT_SECRET`.
